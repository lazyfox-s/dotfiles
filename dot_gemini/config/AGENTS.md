# Global Agent Instructions

すべてのプロジェクトに適用される基本行動原則および共通ガイドラインです。

## 1. コミュニケーションと言語
- 応答、説明、質問、コミットメッセージ等は基本的に**日本語**を使用してください。
- 簡潔で要点を押さえたわかりやすい説明を心がけてください。

## 2. 作業の進め方・行動原則
- **方針の事前共有**: 複数ファイルの変更や設計判断が伴う作業では、いきなりコードを書き換えずに、まず方針・計画（Plan）や変更点の概要をユーザーに提示して確認を取ってください。
- **最小限の変更**: 要求されたスコープに集中し、無関係なコードのリファクタリングやフォーマット変更を勝手に行わないでください。
- **既存コードの尊重**: プロジェクト固有の命名規約、既存のコメント、ディレクトリ構造を尊重してください。

## 3. 安全性と検証
- **ワークスペース外アクセスの制限**: 極力、現在作業中のワークスペース・プロジェクトディレクトリ外のファイルにアクセス（読み込み・作成・変更・削除）しないでください。どうしても外部ファイルへのアクセスが必要な場合は、事前に「なぜそのファイルへのアクセスが必要なのか（理由と影響範囲）」をユーザーに説明し、確認・合意を取ってください。
- **破壊的操作の確認**: ファイルの完全削除や外部影響が大きいコマンドを実行する前に、必ずユーザーに確認してください。
- **検証手順の提示**: 変更を行った後は、構文エラーがないか、テストやビルドが通るかどうかの検証手順をあわせて案内してください。

## 4. Git 運用とコミット方針
- **こまめなコミットの作成**: Git 管理下にあるプロジェクトでは、機能追加・修正・リファクタリングなど一連の作業単位が完了した段階でコミットを作成（またはコミットの実行を提案）してください。
- **コミットの粒度**: push 前に rebase 等で整理・統合するワークフローを前提としているため、コミット粒度は作業ステップ単位の細かめを基本としてください。
- **コミットメッセージ**: プロジェクト固有の規約（`AGENTS.md` や `COMMIT_CONVENTION.md` 等）が定義されている場合は必ずそれに従い、特に指定がない場合は変更内容が簡潔・明瞭に伝わるメッセージ（日本語）にしてください。
- **push の禁止**: リモートリポジトリへの `git push` は、ユーザーから明示的な指示がない限り自動で実行しないでください。
