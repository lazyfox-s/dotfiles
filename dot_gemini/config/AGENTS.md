# Global Agent Instructions

すべてのプロジェクトに適用される基本行動原則および共通ガイドラインです。

## 1. コミュニケーションと言語
- 応答、説明、質問、コミットメッセージ等は基本的に**日本語**を使用してください。
- 簡潔で要点を押さえたわかりやすい説明を心がけてください。

## 2. 作業の進め方・行動原則
- **方針の事前共有**: 複数ファイルの変更や設計判断が伴う作業では、いきなりコードを書き換えずに、まず方針・計画（Plan）や変更点の概要をユーザーに提示して確認を取ってください。
- **最小限の変更**: 要求されたスコープに集中し、無関係なコードのリファクタリングやフォーマット変更を勝手に行わないでください。
- **既存コードの尊重**: プロジェクト固有の命名規約、既存のコメント、ディレクトリ構造を尊重してください。
- **単一コマンド実行（コマンドチェーンの禁止）**: シェルコマンドを実行する際は、`&&` や `;` 等で複数の処理を 1 行に繋げず、原則として 1 ステップずつ分割して個別に実行してください（例: `git add` と `git commit` を `&&` で連結しない、ディレクトリ移動に `cd` コマンドを用いず `Cwd` パラメータを指定するなど）。コマンドの連結はパーミッション自動許可の無効化やサンドボックス保護の形骸化の原因となります。


## 3. 安全性と検証
- **ワークスペース外アクセスの制限**: 極力、現在作業中のワークスペース・プロジェクトディレクトリ外のファイルにアクセス（読み込み・作成・変更・削除）しないでください（ただし、共通記憶・ナレッジ `~/.local/share/agent-memory/` 配下の読み書きおよび `agent-memory` コマンドの利用は許可されています）。どうしてもそれ以外の外部ファイルへのアクセスが必要な場合は、事前に「なぜそのファイルへのアクセスが必要なのか（理由と影響範囲）」をユーザーに説明し、確認・合意を取ってください。
- **破壊的操作の確認**: ファイルの完全削除や外部影響が大きいコマンドを実行する前に、必ずユーザーに確認してください。
- **検証手順の提示**: 変更を行った後は、構文エラーがないか、テストやビルドが通るかどうかの検証手順をあわせて案内してください。

## 4. Git 運用とコミット方針
- **こまめなコミットの作成**: Git 管理下にあるプロジェクトでは、機能追加・修正・リファクタリングなど一連の作業単位が完了した段階でコミットを作成（またはコミットの実行を提案）してください。
- **コミットの粒度**: push 前に rebase 等で整理・統合するワークフローを前提としているため、コミット粒度は作業ステップ単位の細かめを基本としてください。
- **コミットメッセージ**: プロジェクト固有の規約（`AGENTS.md` や `COMMIT_CONVENTION.md` 等）が定義されている場合は必ずそれに従い、特に指定がない場合は変更内容が簡潔・明瞭に伝わるメッセージ（日本語）にしてください。
- **push の禁止**: リモートリポジトリへの `git push` は、ユーザーから明示的な指示がない限り自動で実行しないでください。

## 5. 記憶・ナレッジの共有 (agent-memory)
- **知見の検索・事前確認**:
  - トラブルシューティング時や設計判断時は、`~/.local/share/agent-memory/docs/` 配下のナレッジ（`tips/`, `investigations/`, `decisions/`）を確認してください。
- **調査ログ・知見の記録**:
  - **確定したノウハウ・定石**: `~/.local/share/agent-memory/docs/tips/<tool>.md` に記録・更新してください。
  - **調査中・未解決課題・試行錯誤の過程**: `~/.local/share/agent-memory/docs/investigations/YYYY-MM-<topic>.md` に記録してください。
  - **フロントマター規約**: `investigations/` のドキュメントには必ず以下の YAML front-matter を付与してください：
    ```markdown
    ---
    title: <タイトル>
    status: in_progress # in_progress | blocked | resolved | abandoned
    created: YYYY-MM-DD
    modified: YYYY-MM-DD
    conversation_id: <conversation_id>
    tags:
      - <tag1>
      - <tag2>
    related_files:
      - <path/to/file>
    ---
    ```
- **ドキュメント書式（Obsidian 互換）**:
  - 人間側はナレッジを Obsidian で閲覧するため、標準的な Markdown に加えて以下の記法を適切に活用してください：
    - **コールアウト（Callouts）**: 重要な注意点や補足、Tips の強調（例: `> [!NOTE]`, `> [!TIP]`, `> [!WARNING]`, `> [!IMPORTANT]` 等）。
    - **Mermaid ダイアグラム**: 構成図、フローチャート、関係性の可視化（```mermaid ... ```）。
